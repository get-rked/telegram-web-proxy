# Docker deployment — экспериментальная ветка

Это экспериментальная Docker-native архитектура: закреплённая версия Telegram relay, отдельная панель управления, SQLite для аудита и выбираемый reverse proxy.

**Reverse proxy можно выбрать:**
- **Caddy** — автоматическое получение и продление TLS-сертификатов Let's Encrypt.
- **Nginx** — отдельная конфигурация для TLS-сертификата, который вы заранее размещаете на хосте.

Запускайте только один reverse proxy одновременно: оба используют опубликованные relay порты 80 и 443.

## Подготовка

```bash
cp .env.example .env
# Укажите DOMAIN, ACME_EMAIL и PANEL_PASSWORD (не менее 16 символов).
# config.json, profiles.json, token.key и общий MTProxy secret
# будут созданы автоматически при первом запуске.
# DOMAIN должен быть настоящим DNS-именем вашего сервера.
```

## Вариант 1: Caddy (автоматический TLS)

DNS-запись домена должна указывать на сервер, а входящие TCP-порты 80 и 443 должны быть доступны.

```bash
docker compose --profile caddy --profile mtproxy config
docker compose --profile caddy --profile mtproxy build
docker compose --profile caddy --profile mtproxy up -d
docker compose logs -f caddy
```

Caddy самостоятельно запросит и будет продлевать сертификат. Данные сертификатов хранятся в volume `caddy-data`.

## Вариант 2: Nginx (свой TLS-сертификат)

Nginx ожидает два файла на хосте:

- `docker/nginx/certs/fullchain.pem` — сертификат и цепочка.
- `docker/nginx/certs/privkey.pem` — закрытый ключ.

Получите сертификат любым удобным способом (например, Certbot на хосте), затем:

```bash
mkdir -p docker/nginx/certs
# Поместите fullchain.pem и privkey.pem в эту директорию.
chmod 600 docker/nginx/certs/privkey.pem
docker compose --profile nginx --profile mtproxy config
docker compose --profile nginx --profile mtproxy build
docker compose --profile nginx --profile mtproxy up -d
docker compose logs -f nginx
```

Nginx перенаправляет HTTP на HTTPS, обслуживает панель по `/admin` и передаёт остальные запросы relay. Автоматическое получение/обновление сертификатов для Nginx пока не входит в эту конфигурацию — обновляйте файлы сертификата на хосте и перезапускайте Nginx после обновления:

```bash
docker compose --profile nginx restart nginx
```

## MTProxy backend

Официальный MTProxy собирается из закреплённого upstream commit
`69f2f083b57bbd94932cb9f4f32155f33e719ff1`. Он запускается отдельным контейнером
в сетевом namespace relay и слушает внутренний порт `2398`; статистика доступна
только внутри namespace на `127.0.0.1:8888/stats`. Порт 2398 не публикуется на
хост. Relay подключает профиль к `127.0.0.1:2398`.

**Клиентский секрет должен быть одинаковым в двух местах:**
- `docker/mtproxy/secret` — 32 hex-символа, один newline допустим;
- `secret` соответствующего профиля в `docker/profiles/profiles.json`.

При первом запуске bootstrap генерирует случайный 16-байтовый секрет и атомарно
записывает его одновременно в профиль default и файл MTProxy. Существующие
конфигурации и секреты сохраняются; при изменении hostname существующий
config.json предварительно резервируется. Если секреты в профиле и MTProxy
не совпадают, запуск останавливается без автоматической перезаписи.

При первом старте контейнер загружает официальные `proxy-secret` и
`proxy-multi.conf` с Telegram и сохраняет их в volume `mtproxy-data`. Отдельный
непривилегированный exporter передаёт статистику MTProxy панели через приватную
Docker-сеть; исходный endpoint `8888` остаётся доступен только по loopback.
Upstream рекомендует обновлять routing config ежедневно. Контейнер обновляет
его каждые 24 часа (интервал настраивается через `MTPROXY_REFRESH_INTERVAL` в
секундах), атомарно заменяет файл и перезапускает MTProxy. Если новый конфиг не
позволяет процессу запуститься, предыдущая версия восстанавливается. Секрет
Telegram `proxy-secret` обновляется только при первоначальном скачивании.
MTProxy запускается с одним worker по умолчанию.

Выбрав Caddy или Nginx, добавьте профиль `mtproxy` к команде запуска:

```bash
docker compose --profile caddy --profile mtproxy up -d --build
# либо:
docker compose --profile nginx --profile mtproxy up -d --build
```

Проверка состояния:

```bash
docker compose logs --tail=100 mtproxy
docker compose exec mtproxy curl -fsS http://127.0.0.1:8888/stats
```

## Диагностика, метрики и резервные копии

В панели доступны проверки relay `/healthz` и `/readyz`, доступности MTProxy
stats, а также файла профилей. Метрики включают CPU, RAM, диск контейнера, число
горутин панели, активные сессии/потоки relay, счётчики ошибок, объём трафика и
основные значения MTProxy stats. Показатели relay берутся из официального
Prometheus endpoint закреплённого upstream.

Резервная копия создаётся вручную из панели и содержит `config.json`,
`profiles.json` и manifest в tar.gz. Архивы имеют права `0600`, доступны для
скачивания, автоматически ограничены двадцатью последними копиями. Восстановление
проверяет архив, профильную схему и совпадение секрета default с текущим
MTProxy, создаёт дополнительную копию текущего `profiles.json` и атомарно
заменяет файл. Восстанавливаются именно профили;
активный `config.json` включён в архив для выгрузки/ручного восстановления, но
автоматически не перезаписывается.

## Панель и ограничения текущего этапа

Панель будет доступна по `https://DOMAIN/admin/`. SQLite хранится в именованном томе `panel-data`. Из панели можно создавать, редактировать и удалять профили. Секрет нового профиля показывается один раз при создании; список профилей не раскрывает секреты. Профиль `default` нельзя удалить или переименовать, поскольку его секрет синхронизирован с MTProxy.

Изменения сохраняются атомарно, перед записью создаётся резервная копия `profiles.json`. Admin API relay слушает 8081 внутри приватной Docker-сети; порт не публикуется на хост. Панель опрашивает его напрямую. Relay-supervisor проверяет новую конфигурацию и перезапускает relay только после успешной проверки. При невалидном файле текущий relay продолжает работать. Применение обновления вызывает кратковременный перезапуск relay.

Автоматическое обновление MTProxy routing config и миграция существующей установки ещё не реализованы. **Не разворачивайте эту экспериментальную ветку на рабочем прокси.**
