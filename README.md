# Telegram Web Proxy — установщик и менеджер

**Версия скрипта: 1.0.2**

Bash-скрипт для установки и обслуживания Telegram Web Proxy на серверах Ubuntu/Debian с архитектурой **x86_64**. Разворачивает связку **tproxy-server + MTProxy**, настраивает один из веб-серверов — **Caddy или Nginx**, systemd-службы, локальные правила nftables, TLS, decoy-сайт и ссылку подключения с QR-кодом.

> Для установки и обслуживания нужны права root. Перед запуском на рабочем сервере рекомендуется сохранить резервную копию. Скрипт изменяет системные службы, сетевые настройки и пакеты.

## Возможности

- Интерактивное меню с отображением версии скрипта.
- Установка и обновление tproxy-server и MTProxy.
- Выбор Caddy или Nginx в качестве HTTPS reverse proxy.
- TLS: автоматическое управление сертификатами Caddy либо Certbot/Let's Encrypt для Nginx.
- Генерация секрета MTProxy или использование собственного; форматы `plain` и `dd`.
- Автоматический или пользовательский base path Web Proxy.
- Настройка числа MTProxy workers и максимального количества соединений.
- Создание штатного decoy-сайта Vibe Studio. Если в каталоге уже есть `index.html`, скрипт не перезаписывает сайт и не меняет его права.
- Настройка systemd-служб и локального firewall backend на nftables.
- Проверка конфигурации и готовности сервисов после установки.
- Предварительная проверка DNS/HTTPS-доступности `core.telegram.org` и TCP-доступности Telegram DC.
- Атомарная установка нового бинарника и автоматический rollback бинарника/конфигураций при провале health-check обновления.
- Запуск `go test ./...` при обновлении по умолчанию; пропуск только по явному `--skip-tests`.
- Сокрытие чувствительных значений в выводе диагностических журналов; отключено access-журналирование Nginx для vhost прокси.
- Просмотр текущих параметров, состояний служб и слушающих TCP-портов.
- Формирование Telegram-ссылки подключения и QR-кода (терминал + PNG).
- Диагностика, резервное копирование и восстановление конфигураций.
- Раздельное удаление прокси, штатного decoy-сайта и веб-сервера.

## Требования и подготовка

- Ubuntu или Debian; другие дистрибутивы скриптом не проверяются.
- Архитектура **x86_64**.
- Доступ root или запуск через `sudo`.
- Домен с A-записью, указывающей на публичный IPv4 сервера.
- Доступность входящих TCP-портов **80 и 443** и отсутствие конфликтующих служб на этих портах.
- Доступ сервера в интернет для установки пакетов и загрузки исходников/бинарных файлов.
- Работающие systemd и nftables.

Если используется Cloudflare Proxy (оранжевая тучка), скрипт распознаёт адреса Cloudflare и не требует совпадения DNS-ответа с IP origin-сервера. DNS-проверка выполняется через resolver 1.1.1.1.

Во время установки скрипт устанавливает необходимые зависимости, включая инструменты сборки, `git`, `curl`, `openssl`, `jq`, `qrencode`, `nftables`, `dnsutils` и `netcat-openbsd`. Если подходящей версии Go нет, используется закреплённая версия Go. Caddy устанавливается в закреплённой версии с проверкой контрольной суммы; Nginx и Certbot устанавливаются из репозиториев пакетов ОС.

## Архитектура и порты

Внешние HTTP/HTTPS-запросы принимает выбранный веб-сервер. Он завершает TLS и проксирует запросы на локальный tproxy-server, который взаимодействует с MTProxy.

| Порт | Назначение | Доступ |
|---|---|---|
| TCP 80 | HTTP, редирект и ACME/Let's Encrypt | Открыть извне |
| TCP 443 | HTTPS, сайт и Web Proxy | Открыть извне |
| TCP 8080 | Relay tproxy-server по умолчанию | Только localhost |
| TCP 8081 | Admin/health tproxy-server по умолчанию | Только localhost |
| TCP 2398 | Backend MTProxy в текущей конфигурации | Внутренний |
| TCP 8888 | Служебный порт MTProxy в типовой конфигурации | Внутренний |

Relay и admin endpoint привязаны к loopback-интерфейсу. Backend-порты MTProxy защищаются локальным правилом nftables `inet tproxy_backend`. Не открывайте relay, admin и внутренние порты MTProxy в firewall провайдера или сервера. Для описанной конфигурации входящий UDP не требуется.

Если заданы нестандартные relay/admin-порты, они также должны оставаться доступными только локально. Фактические порты можно посмотреть командой `config`.

## Быстрый старт

### 1. Подготовьте DNS и firewall

Создайте A-запись, например:

```text
proxy.example.com → ПУБЛИЧНЫЙ_IP_СЕРВЕРА
```

Разрешите входящие TCP 80 и 443 в firewall сервера и в панели VPS/облачного провайдера. Убедитесь, что порты свободны.

### 2. Скачайте скрипт

```bash
curl -fsSL https://raw.githubusercontent.com/get-rked/telegram-web-proxy/main/tgweb-install.sh -o tgweb-install.sh
chmod +x tgweb-install.sh
```

### 3. Запустите интерактивное меню

```bash
sudo ./tgweb-install.sh
```

В главном меню доступны установка, обновление, удаление, просмотр конфигурации и инструменты. При установке выберите Caddy или Nginx и укажите домен, email Let's Encrypt, порты, секрет, workers и max-connections.

Секрет можно сгенерировать автоматически или ввести самостоятельно. Допустимы 32 строчных hex-символа либо префикс `dd` перед этими 32 символами.

После установки скрипт проверит готовность relay и выведет параметры подключения, ссылку и QR-код.

## Команды

Общий формат:

```bash
sudo ./tgweb-install.sh <команда> [параметры]
```

### Установка

Интерактивная установка:

```bash
sudo ./tgweb-install.sh install
```

Установка с параметрами:

```bash
sudo ./tgweb-install.sh install \
  --hostname proxy.example.com \
  --web-server caddy \
  --email admin@example.com \
  --port 8080 \
  --admin-port 8081 \
  --workers 1 \
  --max-connections 4096
```

Для полностью автоматической установки добавьте `--non-interactive` (или `-y`). В этом режиме обязательны `--hostname`, `--email`, `--port` и `--admin-port`; если `--secret` не задан, скрипт сгенерирует его автоматически.

```bash
sudo ./tgweb-install.sh install \
  --hostname proxy.example.com \
  --web-server nginx \
  --email admin@example.com \
  --port 8080 \
  --admin-port 8081 \
  --non-interactive
```

### Обновление

```bash
sudo ./tgweb-install.sh update
```

При интерактивном обновлении скрипт загружает сохранённые настройки. Текущие значения предлагаются по умолчанию; Enter оставляет их без изменений. Можно изменить домен, веб-сервер, email, base path, порты, секрет, workers и max-connections.

Текущий секрет по умолчанию сохраняется. Для его замены в интерактивном обновлении ответьте `n` на запрос о секрете, затем введите новый секрет дважды или нажмите Enter для генерации. Это уже предусмотрено общим `update`; отдельная команда ротации не нужна. При обновлении `go test ./...` выполняется по умолчанию. Чтобы сознательно пропустить тесты, передайте `--skip-tests`.

Обновление без вопросов:

```bash
sudo ./tgweb-install.sh update --non-interactive
```

Можно передать только те параметры, которые требуется изменить; остальные берутся из текущей конфигурации.

Перед обновлением создаётся архив rollback в `/opt/telegram-web-proxy/backups/`. Новый бинарник собирается во временный файл и устанавливается атомарным переименованием. После перезапуска проверяются оба локальных endpoint — `healthz` и `readyz`. Если обновление завершается ошибкой до успешного health-check, скрипт восстанавливает сохранённые бинарники tproxy-server/MTProxy, исходники MTProxy, конфигурации и systemd-файлы, затем пытается перезапустить прежние службы.

Rollback охватывает файлы приложения и конфигурации, но не откатывает изменения системных пакетов и не может восстановить сетевые/внешние изменения, выполненные вне установщика. Архивы rollback сохраняются в каталоге backups с правами `0600`.

### Текущая конфигурация

```bash
sudo ./tgweb-install.sh config
```

Команда показывает домен, base path, каталог сайта, конфигурационные файлы, workers, max-connections, email Let's Encrypt, выбранный веб-сервер, формат и значение секрета, адреса и порты, ссылку подключения и путь к QR PNG. Также выводятся состояния служб.

Сохранить текстовый отчёт:

```bash
sudo ./tgweb-install.sh config --output /root/tproxy-config.txt
```

Отчёт создаётся с правами `0600`.

**Важно:** вывод `config` содержит секрет и ссылку подключения. Не публикуйте его, не пересылайте посторонним и учитывайте это при сохранении отчёта или журналировании терминала.

### Диагностика

```bash
sudo ./tgweb-install.sh diagnostics
```

Проверяются состояния systemd-служб, наличие и корректность конфигураций, права файлов, прослушиваемые порты, локальные endpoints `healthz/readyz`, доступность backend MTProxy, конфигурация веб-сервера и TLS. При выводе последних ошибок диагностическая команда маскирует типовые поля секретов, токенов, Authorization и URL-пути. Это фильтрация отображения, а не очистка уже сохранённого journald; не публикуйте исходные системные журналы. Диагностика помогает локализовать неисправность, но не заменяет проверку доступности с внешнего узла.

### Резервная копия и восстановление

Создать архив по пути по умолчанию:

```bash
sudo ./tgweb-install.sh backup
```

Указать собственный абсолютный путь:

```bash
sudo ./tgweb-install.sh backup /root/tproxy-backup.tar.gz
```

Восстановить:

```bash
sudo ./tgweb-install.sh restore /root/tproxy-backup.tar.gz
```

Резервная копия включает доступные конфигурации приложения и MTProxy, файлы веб-сервера, TLS-сертификаты Let's Encrypt, связанные systemd units, каталог сайта, QR и служебные файлы. Архив создаётся с правами `0600`; существующий файл не перезаписывается.

Перед восстановлением скрипт проверяет архив и допустимые пути. После восстановления выполняется `systemctl daemon-reload`, но службы автоматически не перезапускаются. Запустите `diagnostics` и отдельно проверьте работу сервисов.

**Ограничение:** backup/restore — это резервирование конфигураций, а не полный rollback. Архив не возвращает предыдущие бинарники, пакеты, исходники upstream или состояние firewall.

### Удаление

Интерактивное меню: **Удаление**. В нём доступны отдельные действия:

1. Удалить прокси и службы, оставив веб-сервер и сайт.
2. Удалить только штатный decoy-сайт.
3. Удалить выбранный веб-сервер Caddy/Nginx.
4. Удалить всё: прокси, штатный decoy-сайт и веб-сервер.

Удалить прокси из командной строки, оставив веб-сервер:

```bash
sudo ./tgweb-install.sh uninstall --keep-web-server
```

Без `--keep-web-server` скрипт после удаления прокси отдельно спросит, нужно ли удалить выбранный веб-сервер. Для совместимости поддерживается старый алиас `--keep-caddy`.

Полное удаление:

```bash
sudo ./tgweb-install.sh purge
```

Команда удаляет прокси, затем пытается удалить штатный decoy-сайт Vibe Studio. Сайт удаляется только если скрипт распознаёт его по ожидаемому файлу `index.html`; пользовательский или изменённый сайт автоматически не удаляется. В процессе также будет предложено удалить веб-сервер.

Флаг `--yes` (или `-y`) автоматически подтверждает запросы удаления. Используйте его только если заранее проверили последствия:

```bash
sudo ./tgweb-install.sh purge --yes
```

Обычная команда `uninstall` сохраняет каталог сайта. Удаление decoy-сайта доступно отдельно через меню удаления.

## Параметры установки и обновления

| Параметр | Описание |
|---|---|
| `--hostname FQDN` | Домен Web Proxy в нижнем регистре, например `proxy.example.com` |
| `--web-server caddy\|nginx` | Выбор веб-сервера; по умолчанию Caddy |
| `--email EMAIL` | Email для Let's Encrypt |
| `--secret SECRET` | Секрет: 32 строчных hex-символа или `dd` + 32 hex-символа |
| `--secret-prefix plain\|dd` | Формат генерируемого секрета |
| `--base-path SLUG\|none` | Пользовательский путь Web Proxy или `none` для корня домена; без параметра генерируется автоматически |
| `--site-dir PATH` | Каталог сайта; по умолчанию `/opt/telegram-web-proxy/data/website` |
| `--no-site` | Не создавать штатный decoy-сайт |
| `--workers N` | Число MTProxy workers, от 1 до 256; по умолчанию 1 |
| `--max-connections N` | Максимальное число соединений MTProxy; по умолчанию 4096 |
| `--port N` | Локальный relay-порт; по умолчанию 8080 |
| `--admin-port N` | Локальный admin/health-порт; по умолчанию 8081 |
| `--skip-tests` | Пропустить `go test ./...` при сборке |
| `--non-interactive` | Не задавать интерактивные вопросы при установке/обновлении |
| `-y` | В установке/обновлении — non-interactive; в удалении — автоматическое подтверждение |

Relay- и admin-порты должны различаться и находиться в диапазоне 1024–65535. При интерактивной установке скрипт проверяет, не заняты ли выбранные порты.

Пример с собственным секретом и base path:

```bash
sudo ./tgweb-install.sh install \
  --hostname proxy.example.com \
  --email admin@example.com \
  --secret 0123456789abcdef0123456789abcdef \
  --base-path my-proxy \
  --port 8080 \
  --admin-port 8081
```

## Дополнительные настройки и профили

В главном меню открой **Инструменты → Дополнительные настройки**. Внутри доступны управление профилями и настройка публичного сайта (public_upstream).

- **Carrier mode** задаётся отдельно для каждого профиля: https, https-lanes, websocket, websocket-lanes. В интерфейсе режимы подписаны по-русски.
- **Добавление профиля** использует выбор формата секрета (plain или dd), автоматическую генерацию либо ручной ввод с повторным подтверждением, а также выбор Carrier mode.
- **Несколько профилей** поддерживаются с уникальными именами и секретами. Домен, base path, relay/admin-порты и backend остаются общими. Все профили используют один loopback backend и общую политику MTProxy; установщик формирует повторяющиеся аргументы -S для одного процесса MTProxy.
- **Просмотр текущей конфигурации** сразу открывает единственный профиль. Если профилей несколько, сначала предлагается выбрать нужный. В отчёте отображаются имя профиля, его Carrier mode, секрет и ссылка подключения вместе с общими параметрами.
- **public_upstream** позволяет направить публичный сайт на уже работающий HTTP-сервис по адресу http://127.0.0.1:PORT. Менеджер сканирует локальные TCP-порты, проверяет HTTP-ответы и предлагает найденные приложения для выбора. Переключение можно отменить возвратом к локальному public_dir.

Профильные настройки хранятся раздельно: /opt/telegram-web-proxy/config/proxy/profiles/<имя>/profile.json. Общие настройки сервера остаются в config.json, а установщик собирает из профильных файлов агрегированный profiles.json для совместимости с tproxy-server. При первом открытии менеджера существующий profiles.json автоматически раскладывается по каталогам профилей. MTProxy использует общий mtproxy.env, содержащий набор секретов всех профилей.

Обновление сохраняет дополнительные профили и применяет параметры установки/обновления к основному профилю default. Изменение Carrier mode в менеджере затрагивает только выбранный профиль. При добавлении/удалении профиля набор секретов MTProxy синхронизируется, затем службы перезапускаются.

## Проверка качества кода

В репозитории настроен GitHub Actions workflow `Shell checks`. Локально можно выполнить тот же набор базовых проверок:

```bash
bash -n tgweb-install.sh
bash -n tests/test_installer.sh
shellcheck --severity=warning --shell=bash tgweb-install.sh tests/test_installer.sh
bash tests/test_installer.sh
```

Обновление запускает upstream `go test ./...` перед сборкой, если не указан `--skip-tests`.

## Ссылка подключения и QR-код

После установки или обновления скрипт выводит Telegram-ссылку и QR-код в терминале. Команда `config` повторно формирует ссылку и QR по текущей конфигурации.

PNG сохраняется в:

```text
/opt/telegram-web-proxy/qr/proxy-qr.png
```

Файл создаётся с правами `0600`, каталог QR — с ограниченными правами. Секрет, ссылка и QR-код дают доступ к прокси: не публикуйте и не передавайте их посторонним.

## Файлы и каталоги

Основной каталог приложения:

```text
/opt/telegram-web-proxy/
├── bin/       # бинарники и служебные скрипты
├── config/
│   ├── proxy/ # config.json, profiles.json, profiles/<имя>/profile.json
│   └── mtproxy/
├── data/
│   └── website/ # decoy-сайт по умолчанию
├── src/       # исходники tproxy-server и MTProxy
├── systemd/   # шаблоны/копии unit-файлов
├── qr/        # QR-код подключения
└── backups/   # резервные копии по умолчанию
```

Системные файлы и службы:

| Путь / имя | Назначение |
|---|---|
| `/opt/telegram-web-proxy/config/proxy/config.json` | Настройки tproxy-server, домен, адреса и каталог сайта |
| `/opt/telegram-web-proxy/config/proxy/profiles/` | Отдельный каталог настроек каждого профиля |
| `/opt/telegram-web-proxy/config/proxy/profiles/<имя>/profile.json` | Имя, секрет, backend и Carrier mode выбранного профиля |
| `/opt/telegram-web-proxy/config/proxy/profiles.json` | Сводный файл всех профилей для tproxy-server |
| `/opt/telegram-web-proxy/config/proxy/acme-email` | Email Let's Encrypt |
| `/opt/telegram-web-proxy/config/proxy/web-server` | Выбранный веб-сервер |
| `/opt/telegram-web-proxy/config/mtproxy/mtproxy.env` | Параметры MTProxy |
| `/opt/telegram-web-proxy/qr/proxy-qr.png` | QR-код подключения |
| `/usr/local/bin/tproxy-server` | Совместимая ссылка на бинарник tproxy-server |
| `/usr/local/bin/mtproxy` | Совместимая ссылка на бинарник MTProxy |
| `/usr/local/bin/refresh-mtproxy-config` | Совместимая ссылка на служебный скрипт |
| `/etc/caddy/Caddyfile` | Конфигурация Caddy |
| `/etc/nginx/sites-available/tproxy-server` | Конфигурация Nginx |
| `/etc/nginx/conf.d/tproxy-websocket-map.conf` | WebSocket map для Nginx |
| `/etc/letsencrypt/` | Сертификаты и настройки Certbot при использовании Nginx |
| `/etc/systemd/system/` | Установленные systemd units |
| `/var/www/letsencrypt` | ACME webroot |

Caddy и Nginx — альтернативные варианты: для Web Proxy одновременно используется выбранный веб-сервер. При переключении скрипт удаляет конфигурацию предыдущего веб-сервера, если она была зарегистрирована как текущая.

## Безопасность и важные замечания

- Не передавайте третьим лицам секрет MTProxy, Telegram-ссылку, QR-код и отчёт `config`.
- Не открывайте в интернет локальные relay/admin-порты и backend-порты MTProxy.
- Не запускайте `purge --yes`, не проверив, какой веб-сервер и decoy-сайт будут удалены.
- Существующий пользовательский сайт не перезаписывается при установке, если в целевом каталоге уже есть `index.html`.
- При обычном `uninstall` каталог сайта сохраняется. При `purge` скрипт удаляет только распознанный штатный decoy-сайт.
- Не размещайте собственные изменения в каталоге исходников upstream: при обновлении он синхронизируется с закреплённой версией.
- Перед изменениями на рабочем сервере создавайте резервную копию и проверяйте восстановление на тестовой системе.
